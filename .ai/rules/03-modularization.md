# Modularization Rules

- Logical modules with clear single responsibility
- Small, focused functions/classes
- No tight coupling between modules
- Extract common functionality to reusable components
- Composition over inheritance
- Shared utils for repeated logic
- Loosely coupled, highly cohesive
- No circular dependencies
- Dependency injection
- Unit tests for business logic
- Integration tests for module interactions
- Mock external deps in tests
- High test coverage on critical paths
